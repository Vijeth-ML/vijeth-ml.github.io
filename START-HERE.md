# Start here — publish your portfolio safely

1. Open `README.md` and follow the GitHub Pages instructions.
2. Before publishing, review `projects.json`. It is based on titles and descriptions in the provided e-portfolio ZIP, and some details are deliberately marked as needing verification.
3. Remove or rewrite any project that you cannot explain confidently in an interview.
4. For each project you want to feature, create a separate repository and use `projects/PROJECT_README_TEMPLATE.md`.
5. Add actual results only after running the code. Add your personal contribution statement for group work.
6. Enable two-factor authentication on GitHub and never commit `.env` files or credentials.

## Recommended first month
- Week 1: publish the portfolio and clean up one project repository.
- Week 2: make one project reproducible from a fresh environment; add tests and a clear README.
- Week 3: run baseline experiments and add error analysis.
- Week 4: start a small, original exoplanet/light-curve experiment with a clear research question and documented dataset provenance.

This is a practical sequence, not a requirement to commit every day.
